Keyboard & accessible integration

Native controls supply their browser semantics. Add descriptive names and a host-level keyboard path wherever the visual view is not an interactive control.

Component Keyboard behavior Host responsibility
Slider Native range input arrows and range navigation Unique label, valid bounds and meaningful unit
Knob Arrows step; Home/End select bounds; disabled leaves tab order Descriptive accessibleLabel when needed
Toggle / transport Native buttons activate with Enter/Space Names for icon-only actions; correct controlled state
CanvasWaveform Interactive slider: arrows adjust 1%; Home/End seek to bounds Ratio state; preserve a keyboard path with custom handlers
TimelineViewport Focusable scroll container; browser scrolling Meaningful viewport label and visible focus
TimelineWaveform SVG image, no built-in keyboard seeking Separate source-time range input, as in the examples
TimelineRegionLane Native region buttons seek to the region start Concise readable labels
TimelineZoom Native buttons/range; disabled at limits Same zoom state as the viewport
Playhead / meter Visual and aria-hidden Alternative textual information when needed

Retain visible focus when replacing styles. Test your theme in forced colors, with zoomed text and at narrow widths. Do not convey mute/solo state solely through color; ToggleButton exposes aria-pressed.

The library installs no global shortcuts. Scope additional shortcuts to your application and avoid intercepting typing or unrelated controls. Stop demo/host animations when no longer needed and honor reduced motion in host-owned animation.
